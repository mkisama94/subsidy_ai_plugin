# 公式資料ダウンロード情報のキャッシュ：実装結果

確認日：2026年9月27日。コードバージョン：0.12.0。

Phase 1のサーバー機能を実装し、ローカルのWorker・D1・MCPで動作を確認した。本番配備、本番DBへのマイグレーション、対象公募回の運営承認、実モデルによる分類品質の評価は未実施。

## 実装内容

| 機能 | 内容 |
|---|---|
| 共通レジストリ | 既存の公開APIキャッシュと分離したD1の4テーブル。制度・公募回・掲載元・資料・収集履歴を関連付ける |
| 収集 | 運営登録した公式HTMLとJグランツ添付メタデータを処理。ファイル本体・Base64は保存しない |
| 分類 | 資料種別・用途・利用段階を整理。根拠・モデル・版が一致する分類を再利用。AI未接続時はルール分類と原文名を返す |
| 再確認 | 掲載ページとファイルリンクの確認日時を分離。304・失敗・期限切れ・消失を扱い、不完全な収集で現行一覧を置き換えない |
| 公開取得 | 読取専用の `get_subsidy_documents`。公募回不明の資料を通常一覧に混ぜず、必要時だけ参考情報として返す |
| 運用 | 掲載元登録・再確認予約・停止・復旧、定期処理、日次AI呼出上限、URL・DNS・転送先・応答容量の検査 |

個別企業に必要な資料セットの判定、申請書の記入、原本の代理配信は対象外。

## 確認結果

| 確認 | 結果と範囲 |
|---|---|
| 自動テスト | 106件成功、失敗・スキップなし。既存機能と追加機能を含む |
| 型チェック | `npm run typecheck` 成功 |
| 配備用ビルド | `wrangler deploy --dry-run` 成功。実配備はしていない |
| 実DB | 隔離したローカルD1に0001〜0004を適用。収集・保存・取得の動作を確認 |
| MCP定義 | ローカルの16ツールと4種の注釈を確認 |
| 実ページ | ものづくり・新事業進出・持続化の3公式掲載ページから40・22・2件を抽出。種別別に抽出した少数のリンクでHTTP 200を確認 |
| Workerでの収集 | ものづくりの掲載ページから40件を保存し、MCPで取得。試験用の架空IDと未確認の公募回対応を使用し、全40件が参考情報に分離されることを確認 |
| 再実行・復旧・停止 | 304での再確認、過去の正常結果への復旧と確認日時の維持、停止後の非表示を実際のローカルMCPで確認 |
| AI | 出力検証・分類再利用・失敗時処理・同時実行時の予算制御をテスト。実モデルの呼出しと品質評価は未実施 |

試験用ローカル掲載元は停止し、検証用Workerも終了した。本番用の掲載元設定は空、公開・収集・AI分類の各機能フラグはfalseのまま。
