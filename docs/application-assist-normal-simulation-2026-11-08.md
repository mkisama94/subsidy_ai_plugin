# 申請準備の正常系・未充足ケース再現（2026-11-08）

## 問題と変更

模擬証明書・登録回答をそろえても実原本の確認要求が残り、質問の後にガイドが生成されない試験があった。従来の個別ケースの「不足あり」を一般スキルの期待結果として固定していた点を除去し、模擬完成、要件未充足の確認結果、実申請準備を区別した。

計画文がレビュー済みなら数値未充足でも準備完了にできる穴も修正した。`projectionPeriods` と根拠付きの `plan.1`〜`plan.3` の4項目を要求し、営業利益・人件費・減価償却費・総労働時間から生産性を再計算する。給与増と同額の利益減を相殺すると生産性は上がらない。表示上の丸めで不足を通さない。

対応範囲は従来の2026年第7次以降・通常枠・標準補助率・過去受給なし・150万円未満。目標の1年後3％と3年間年平均3％、基準・計画年度の根拠は[公募要領](https://it-shien.smrj.go.jp/pdf/it2026_kaitei_koubo_tsujyo.pdf)の印刷7・30ページ（2026-11-08閲覧）。他の枠・既受給・加点条件の適用範囲を拡大したものではない。

`application-assist:simulate` は明示された合成入力専用。実ファイルのハッシュ・PDFページ数・引用を検証して出力する。レビュー/API照合/登録/画面対応の完了状態はフィクスチャであることを保持する。入力JSONにない回答は補完せず、実案件はこの入口で拒否する。PDF全般の自動抽出・意味理解の精度を保証するものではない。

出力に `assessment-summary.html` を追加し、入力ガイド、数値計画、添付対応、未充足の理由を一つの入口で確認できるようにした。`completionKind` は模擬完成と実案件の準備完了を区別する。

## 非公開テスト一式

内部資料フォルダに v1.3 の正常系を新規作成し、既存 v1.2 の原本を変更せず再利用した。直近月資料を含む01〜09に、正常系回答と3年間の数値計画を載せた10を追加した。実会社を基にした資料・法人識別子・財務値・原本ハッシュはこの文書や公開fixtureへ転載しない。

- 正常系は独立したcaseId。自己宣言済み、模擬同意・登録・受付済み、追加売上と給与増の仮想計画を明示する。
- 未充足ケースは以前の未実施・改善見込みなしの条件を保持する。正常系への無断変更をしない。
- `simulation-input*.json` は入力、`expected-results.json` は評価用。評価ファイルは入力値の補完に使用しない。
- `run-demo.ps1` は2ケースの出力と期待状態・不足ID・必須ファイルを検査し、`last-run.json` と `結果を開く.html` を生成する。
- データZIPに原本と再現入力を同梱し、実行結果・非公開レビュー記録は混在させない。

## 到達点と残る確認

資料照合→数値判定→模擬ガイド・添付対応表・確認結果の出力、という最小経路は通過した。新規チャットでモデルが初回見積から自律的に質問を終えられるかの独立評価、インストール済み版の読み込み、公式全画面での操作受入は未実施。今回の合成再現の合格を、その受入合格とは扱わない。署名・外部送信・申請提出・公開は行っていない。

将来Web UIへ移す場合には、資料受付・確認済み回答・不足理由・最終成果物を案件単位で保存・表示する入口をこのデータ契約につなげられる。Web UIの実装・公開は今回の範囲に含めない。
