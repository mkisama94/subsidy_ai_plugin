# 手元資料の一括添付と短い受領確認

対象は申請準備中の法人。公開情報で補える入力を減らし、必要な書類は添付で読み取る。添付できないときも、理由に合う取得・確認案内で続ける。本人ログイン型の税務APIを接続する工程は設けない。

## 最初に確認する順序

1. 会話から会社・法人番号・年度・枠・既知の決算期と資料を引き継ぐ。法人が未確定なら会社選択へ戻る。年度・枠未確認のまま2026年通常枠を既定にせず、公開情報調査と手元資料の仮整理を進める。
2. 添付済みの資料は先に読む。読み取り可能なPDF・画像・表計算ファイル等をホストの機能で確認し、公開情報の照会待ちだけを理由に止めない。同じ会話で有効な照会結果・原本で満たす項目は再照会・再質問しない。
3. 不足する会社・財務情報は、以下の公開APIで取得できるか先に確認する。取得できなければ、その理由を短く伝え、決算書等で補う。API利用のたびに同じ許可を求めず、ツールが利用不可なら実行したふりをしない。
4. 適用要領・入力マニュアルから必要資料を内部で整理し、今添付する手元資料だけを3〜4グループにまとめる。公開照会や決算確認待ちだけを理由に、同じ作業で用意できる人事・勤怠・給与資料を小出しにしない。証明書の取得と販売会社の同意書は別工程として早めに予告し、[取り寄せと待ち時間の案内](document-follow-up.md)に進む。

## 手元資料を意味のある単位でまとめる

必要性は申請項目から判断する。人数・労働時間が必要と分かるなら、その根拠となる名簿・勤怠は給与資料と同じグループで案内する。「決算書を確認したら次は勤怠」のような順番を設けない。現在の操作に関係する受領状態だけを表示し、同じ内容を満たす複数形式・帳簿は「いずれか」として重複提出を避ける。

以下は案内漏れを防ぐための内部参照表であり、そのまま全行・全列を利用者に出さない。適用年度・枠・入力項目に合わせて正式名称、期間、取得先、用途、状態を把握する。利用者には「決算書（BS・PL）」「人事・給与・勤怠資料」「入力に必要な補足明細」のようにまとめ、期間と今の操作を添える。全案件共通の公式添付一覧ではない。

| 資料・帳簿 | 用途と確認する内容 | 対象期間・取得先の案内 |
|---|---|---|
| 貸借対照表・損益計算書 | 公式提出要件と財務入力。会社名・期間・単位・全ページを確認 | 適用要領の直近確定期。経理・顧問税理士・会計ソフト |
| 役員・従業員一覧（労働者名簿等、必要項目を満たす資料） | 人数と集計対象の確認。役員／従業員、雇用区分、入退社・在籍期間を把握 | 人数・生産性等の対象時点・期間をマニュアルで確認。人事・労務担当 |
| 勤務記録簿・出勤簿・タイムカード・勤怠システム出力のいずれか | 労働時間の根拠。月別・対象者別の実績と年度内の欠落を確認 | 生産性計算に必要な期間をマニュアルで確認。人事・労務担当・勤怠システム |
| 賃金台帳・給与集計表等、必要な内訳を満たす資料 | 人件費・給与支給総額・役員報酬等の確認。決算書で必要な内訳まで読める項目は重複不要 | 各入力項目の必要期間。経理・給与担当・顧問税理士等 |
| 販管費・製造原価等の明細、減価償却費の集計・固定資産台帳等 | 決算書に必要な人件費・減価償却費の内訳がない場合の補足。初回から「内訳がない場合」と条件を明記 | 対象となる決算期。経理・顧問税理士。該当明細だけでよく、全帳簿一式を要求しない |
| 履歴事項全部証明書・法人税納税証明書 | 適用要領に基づく公式提出用。種類・発行期限を確認 | 2026年通常枠の法人では登記は発行3か月以内、納税は直近分の「その1」または「その2」。他年度・枠は再確認。法務局・税務署 |
| 見積書・販売会社の所定書式 | 見積内容と販売会社手続き。受領済み見積は再要求しない | 対象案件・年度・版。選択済み販売会社 |
| 株主構成表・資本政策表・株主名簿等の必要部分（条件付き） | 資本関係等の資格確認。公開情報と受領済み資料で埋まらない項目の根拠が必要な場合。全件の公式添付必須とはしない | 適用要領が指定する基準日。[資本関係の確認](../../company-research/references/ownership.md)で調査し、不足だけを会社管理担当等へ確認 |
| 補助率引上げ・加点・過去受給等に伴う追加資料 | 該当条件と資料名を初回から表示。希望・該当が確定していないものを必須取得にしない | 適用要領で確認した期間・取得先。未確定事項だけを確認 |

勤怠だけでは対象者全員の在籍・役員区分まで分からないことがある。名簿や給与資料と突き合わせ、見積のライセンス数を従業員数に代用しない。資料にない役員等の時間をゼロ・一律の標準時間で補わない。制度上の従業員数、人件費・賃金の集計対象、生産性の労働時間の対象は、それぞれ適用マニュアルの定義に合わせる。最新決算・生産性・賃金計画で期間が異なれば一覧に明記し、全てを決算期と同じにしない。

添付欄で複数ファイルを受け取れる場合は、手元にある対象資料の一括添付を案内する。添付非対応の質問UIへ誘導しない。枚数等の制約があれば分割して受け取り、各回の確認待ちを強制しない。証明書・同意書が未着でも読取りを進め、既に一緒に届いた場合は受け付けて取得工程を省く。必要のない個人情報は求めず、集計用資料は社員番号等で照合できれば氏名を省略できる。公式提出の必要項目を隠してよいとは案内しない。

追加依頼は、例えば人件費内訳の欠落、勤怠に含まれない集計対象者、読めないページ、条件変更で必要となった書類など、資料を見て初めて判明した理由を短く示して該当部分だけ求める。最初から必要と分かっていた資料の案内漏れは依存関係と説明せず、一覧を訂正する。契約・支払等の交付後に発生する証憑は後続手続きとして見通しを伝え、申請準備のため今から発注・支払いを促さない。

## 公開APIで補う

会社名・所在地から確定した法人番号で `get_corporate_identity`、必要に応じて `get_company_profile` を使用する。財務情報の確認には `get_company_activities` の `corporate_number` と `activity_types: ["finance"]` を指定する。過去受給を確認する段階では必要に応じて `subsidy` を追加する。必要な種類を指定し、毎回8種類すべてを取得しない。

- 公開APIへ送るのは法人番号や公開情報の検索条件のみ。決算書・OCR全文・給与値などの私有情報を送らない。
- API取得成功、データ掲載なし、項目の空欄、取得失敗、機能利用不可を分ける。`partial` や種類別の `errors` がある場合、財務取得が成功したか個別に確認する。項目数1でも財務数値がそろったとは限らない。空欄・未取得を0円・0人にしない。
- 数値ごとに法人、対象期間、単体／連結、科目の定義、通貨・単位、出典、取得日、更新日を確認する。年度不明・旧年度・連結値・科目不一致は申請値へそのまま転記しない。過年度は過年度として保持する。
- gBizINFOの財務は主にEDINET由来で、有価証券報告書を提出していない法人には財務情報がない。決算公告も公開を許諾した分だけで、全企業の決算書がそろう仕組みではない。官報由来の決算公告と `finance` の返却を同一視しない。
- 必要に応じて、利用可能な公開閲覧機能から出典のEDINET書類等を確認する。汎用のEDINET財務取得ツールが利用できると仮定したり、親会社確認用ツールを財務取得用に流用したりしない。
- 公開財務は入力候補・原本との照合に使う。対象と意味が合う値は本人確認に提示できるが、API成功だけで申請資格・正式添付・原本確認済み・転記準備完了にしない。既存の `enrich/import-api` はその取込み対象だけに使い、財務値を未対応フィールドへ流し込まない。
- 本人ログインが必要なe-Tax、マイナポータル等のAPI連携・権限付与へ誘導しない。政府API側のサービス用トークンと本人認証を混同しない。GビズIDは補助金申請時の本人認証であり、非公開決算へのアクセス権を与えない。

## PDF等を受け取れたとき

法人名、決算期間、貸借対照表と損益計算書の有無、ページ欠落、金額単位を読み取る。年度・期間は表紙だけでなく各表も確認する。文字抽出が崩れた場合は画像と照合し、対応機能があるときのみローカルOCRを利用する。ホストが読めない形式は読み取り済みにしない。

表示は添付ミスに気付ける短いサマリにする。決算書は会社名、第何期（記載がある場合）または決算期間、売上、利益の種類と額。人事資料は期間・役員と従業員の人数・受領状況を1文程度にまとめる。例えば「A社・2025年度（2025/4〜2026/3）の資料を受け取りました。売上1億円、営業利益800万円です。人事資料も同期間・役員1名／従業員5名分です。」。例の金額・会社・人数を他案件に転用しない。

全科目、個人別給与、日次勤怠、検算件数は通常表示しない。明確な問題がなければ数値一覧への再承認を挟まず次へ進む。別法人、期間違い、欠月、読めない箇所などを見つけたときだけ「3月分の勤怠がありません。3月分だけ追加してください」のように影響と修正を短く伝える。期数不明を添付ミス扱いせず、期間が分かれば使う。

読取りは添付の識別と申請入力に必要な範囲に限り、会計・労務処理の適否や全明細の正確性レビューは標準工程にしない。正式入力に必要な計算を行う段階では単位・期間・科目定義を確認し、人件費・給与支給総額・役員報酬等を混同しない。総労働時間を人数から推定せず、疑義のある値は未確定のまま残す。詳しい内訳や計算過程は利用者が求めた場合、またはその判断が必要な場合に示す。

チャットへの添付・読み取りと、申請マイページへの正式添付は別の状態。提出形式・対象年度・ページ・サイズ等は適用する公式案内で確認し、チャットで読めたという理由で提出可能と断定しない。

## 添付できないときの分岐

理由がまだ不明なら一度だけ「紙で持っている／手元にない／添付方法が分からない／ここでは共有しない／その他」の短い選択を示す。理由・利用端末・ソフトが分かっているなら、その状況に合う操作へ直接進む。質問用UIが添付非対応なら、そこでアップロードを求めない。

| 状況 | 今案内する一つの操作 | 残す確認 |
|---|---|---|
| 紙のみ | ホストが画像を読めるなら、一覧のうち手元にある必要資料を写真またはスキャンPDFでまとめて添付する。会社名・期間・単位・数字が読めるように全ページを撮る。貸借対照表と損益計算書を順番待ちにしない | 相談用の写真がそのまま公式提出に使えるとは限らない。正式提出用の形式・全ページは別途確認 |
| 会計ソフトにある | 決算書・財務諸表の出力から対象期の貸借対照表・損益計算書をPDF保存する案内。ソフト名が既知なら再質問せず、具体的メニューは公式ヘルプや実画面を確認できた範囲で示す | 未確認のメニューや機能を創作しない。試算表と確定決算書を区別 |
| 経理・税理士が保管 | 下の依頼文を対象期に合わせて用意する。宛先の役割と資料名を明記し、利用者が送る | 取寄せ依頼作成と送信・受領は別。待つ間に確認済み会社情報や見積を整理 |
| 添付操作が不明・ホストに添付機能がない | 確認できるチャットの添付操作を案内。操作が見えなければ利用端末・アプリだけを確認し、利用できる貼付け等へ切り替える | 存在しないボタン、添付不可の質問UI、無関係な外部アップロード先を案内しない |
| 本文の貼付け・手入力なら可能 | まず表題・対象期間・金額単位を受け取り、次に必要な科目だけを小分けに確認。公開値・既読値を聞き直さない | 自己申告・原本未照合として保持。入力値から公式決算書を作ったり、添付済みにしたりしない |
| 共有を希望しない | 共有を繰り返し求めず、本人が手元で確認する項目と公式提出用に確保する資料を示す | チャットでの原本照合は未実施。書類に依存しない準備は継続 |
| 決算未確定・書類がない | 決算の確定状況と利用可能な直近確定期を確認する。必要書類を満たせるか適用要領に照らす | 試算表や見込み値を確定決算として代替しない。書類がそろう前に正式入力準備完了としない |

資料の文字が不鮮明、片方の表のみ、旧年度、別法人等なら該当箇所だけ確認し、全資料の一律再提出を求めない。会話内で扱う必要のない情報は求めないが、公式提出書類の必要箇所を隠してよいと案内しない。

## 取寄せ依頼文

対象期が確認できた場合は次の文面へ実際の期間を差し込む。未確認なら「直近の確定した事業年度」として、決算期間も回答に添えてもらう。架空の期末日や担当者・宛先を作らない。

> 経理ご担当者様／顧問税理士様
>
> 補助金の申請準備のため、直近の確定した事業年度の貸借対照表・損益計算書を、全ページがそろったPDFでご用意ください。会社名・決算期間・金額単位が分かるものをお願いします。PDFが難しい場合は、受け取れる形式をご案内ください。対象の決算期間も併せてお知らせください。

上の決算書依頼だけで必要資料の案内を終えない。初回一覧で必要と分かる賃金台帳・給与集計表や勤怠・名簿等も、対象期間と用途を添え、実際の保管担当への依頼にまとめる。保管先が分かれていれば経理・人事等の宛先ごとに分け、全てを税理士が持つとは仮定しない。決算内訳は「必要科目が決算書にない場合」の条件を添える。用途のない税務申告一式・帳簿一式は要求しない。依頼文は準備のみで、明示的な送信依頼なしに社内・税理士・販売会社へ送らない。

## 制度上の資料と確認済みの出典

以下は2026-11-07に確認した範囲。適用年度・枠・改訂版を確認して利用する。

- [2026年通常枠の公募要領](https://it-shien.smrj.go.jp/pdf/it2026_koubo_tsujyo.pdf) 本文21ページ「3-2（2）」：法人の交付申請には履歴事項全部証明書、直近分の法人税納税証明書、直近分の貸借対照表・損益計算書を列挙。代替書類は認められず、追加書類を求める場合がある。APIの数値や手入力はこの添付義務を免除しない。他年度・他枠へ一律適用しない。
- [交付申請の手引き](https://it-shien.smrj.go.jp/pdf/it2026_manual_kofu.pdf)：最新決算、生産性、賃金計画等の対象期間・科目定義は該当枠の説明で個別に確認する。
- [交付決定後の手続き](https://it-shien.smrj.go.jp/aftergrantdecision/measures/)：導入後の事業実績報告は発注・契約・納品・支払い等の証憑、後続の事業実施効果報告は効果の報告。申請時に用いる直近決算と、導入後の年度の実績を混同しない。
- [gBizINFO API案内](https://content.info.gbiz.go.jp/api/index.html)、[財務情報の収集範囲](https://help.info.gbiz.go.jp/hc/ja/articles/5023358112030)、[決算公告の収集範囲](https://help.info.gbiz.go.jp/hc/ja/articles/5029817495966)：公開データの収録範囲を説明する根拠。API接続成功や実会社の取得結果は実行記録で別途確認する。

## 次の操作と状態

利用者には短い受領サマリと次の一つの操作を表示する。必要なときだけ現在の作業に関係する不足を添え、毎回全資料の一覧を再掲しない。内部では未受領／読取り中／対象期間等の確認待ち／公式添付用の準備済み／公式画面への添付済みを区別する。受領を資料の正確性・適法性のレビュー完了にしない。内容確認用帳簿を公式添付必須に変更しない。

添付不可だけで相談を打ち切らず、取得・本人確認・独立した準備を続ける。必須書類・根拠が不足する間は公式転記準備完了にしない。公開情報調査は原本未受領でも可能だが、ローカル案件への取込みと最終判定は既存の原本照合・検証・レビュー条件を保つ。
