# Intelligent UIを活かした補助金相談の改善案

作成日：2026年10月27日。状態：提案。機能の実装・本番配備・更新申請は未実施。

## 推奨する更新の目的

次期版（仮称1.2.0）は「補助金候補を比較し、申請前の確認事項を整理し、専門家への相談準備まで進めやすくする」更新とする。先行して修正した日本語の掲載文も同梱する。

Intelligent UIによる表示を活用するため、相談スキルとツールの返却データを見直す。候補比較、未確認条件、相談準備の3つを今回の中心とし、金額の自動試算とチャットをまたぐ案件保存は後続とする。

## 公式仕様から分かったこと

- Intelligent UIは、ChatGPTが質問に応じて文章、図、ボタン、フォームなどを組み合わせる機能。表示は質問、設定、利用環境によって変わり、開発者が常に同じ画面を保証するものではない。
- 現在はChat向けで、WorkとVoiceでは利用できない。ProプランとProの推論設定は別であり、GPT-6 Astraを使うPro推論設定も対象外。
- 一部のチェックリスト等は同じチャットの再読み込みで状態を保持できるが、チャット間での引き継ぎは保証されない。プラグインの永続的な案件管理としては扱わない。
- MCP Apps UIは、プラグインがHTML等を返して表示・操作を実装する別の仕組み。固定の画面や確実なツール呼び出しが必要な操作にはこちらを検討する。

根拠：[Intelligent UI in ChatGPT](https://help.openai.com/en/articles/20001598-intelligent-ui-in-chatgpt)、[GPT-6 and Intelligent UI for everyone](https://openai.com/index/gpt-6-for-everyone/)、[Add UI to your MCP server](https://developers.openai.com/plugins/build/chatgpt-ui)。確認日：2026年10月27日。

今回確認した公式資料では、プラグインがIntelligent UIを強制的に有効化する専用の設定や、生成されたすべてのボタンを任意のMCPツールへ直接結び付ける契約は確認できていない。スキルとデータを整えた上で、ChatGPT実環境で効果を検証する方針とする。structuredContentの追加自体をIntelligent UIの必須条件や有効化方法とは説明しない。

## 今回実装を推奨する3機能

### 1. 候補を比較して選ぶ

候補が複数ある場合に、初回は原則3件程度を見比べやすく提示する。実際の取得件数以上に候補を増やさず、候補が1件なら単独の概要、0件なら検索範囲と次の確認方法を示す。

- 制度名、年度・公募回、受付状況、締切、対象経費、補助率・上限、対象地域を表示する。
- 「事業との関連」「申請前の未確認事項」「公式情報へのリンク」を近接して表示する。
- 検索段階の値と、詳細・公募要領まで確認した値を区別する。
- 候補の選択を受けて詳細確認や企業条件照合へ進む。生成UIで操作を提供できない環境では「候補Aの条件を確認して」などの通常の会話で進める。
- 過去の採択率は必要なときだけ詳細で示し、候補の推奨順位や個別企業の採択確率に置き換えない。

利用者の変化：長い説明を読み比べなくても、調べたい候補と次の確認点を選べる。

### 2. 申請前の確認事項を整理する

選んだ制度に対して、確認する条件を一覧にする。会社が未特定の場合は、国税庁の検索結果から正式名称・法人番号・所在地を示して選択を促す。同名の別法人を自動決定しない。会社が未特定でも、制度そのものの調査は可能な範囲で進める。

- 「公的情報で確認できたこと」「利用者からの申告」「未確認」「情報の不一致」を区別する。
- 事業との相性、申請資格、資金・実施体制の3軸を混同しない。
- 不足情報は必要な項目だけ尋ね、既に聞いた地域・従業員数等を再質問しない。
- チェック操作は「確認作業の進捗」や「利用者が申告した内容」を表す。チェックしただけで公的確認済み・申請資格ありに変えない。
- 年度や実施場所、企業条件を変えたら、旧評価をそのまま利用せず、影響する条件を再確認する。

利用者の変化：「利用できるか不明」で止まらず、何を確認すれば検討を進められるかが分かる。

### 3. 専門家への相談準備を進める

既存の相談メモ生成を、確認事項・相談先・資料の準備状況が対応する形で提示する。

- 「専門家に聞くこと」「準備する資料名」「相談までに確認する日付」を整理する。
- 資料の準備状況と、申請要件の充足状況を別に扱う。準備済みのチェックを資格確認に流用しない。
- 同じチャットの最新情報から相談文を生成し直し、制度名、公募回、出典、残る確認事項を引き継ぐ。
- 相談文をコピーして使える形で提示する。メール送信や申請の代理提出は行わない。
- 決算書等の非公開資料は資料名だけを案内し、プラグインへのアップロードや保存を前提にしない。

利用者の変化：「専門家へ相談してください」という案内から、質問と準備物が揃った状態へ進める。

## 想定する一連の体験

1. 「東京都で飲食店を経営しています。厨房設備の更新に使える補助金を探して」と依頼する。
2. 実際に取得した候補を、条件・受付状況・出典付きで見比べる。
3. 気になる候補を選び、会社と事業計画について不足している条件を確認する。
4. 確認できたことと残る質問を分け、必要資料の準備一覧を見る。
5. 選んだ候補と最新の確認内容を反映した相談文を取り出す。

これは提案する操作の流れであり、固定のボタン構成や画面の再現を保証するものではない。UIが出ない場合も同じ内容を表・箇条書き・会話で完了できる。

## 実装の方針

### 第1段階：小さく実機検証する

公開版スキルを基に、テキスト表に限定する指定を改める。候補比較、条件確認、相談準備ごとに、表示すべきデータ・根拠・次の行動を定義する。既存ツールの結果を使い、ChatGPTのChatで表示と継続操作を確認する。

生成UIからの選択内容が次の会話に引き継がれるか、確認済みの情報が崩れないかを先に検証する。ここが成立しなければ、スキル変更だけで「対応済み」としない。

### 第2段階：返却データを整える

まず検索・詳細・法人条件照合・相談メモの対象ツールに絞って、既存のJSONテキストを維持しつつ構造化出力を追加し、出力契約を定義する。UIのためだけにツール数を増やすことは必須としない。

表示に必要な要素は、制度ID、公募回、根拠URL、取得日時、条件の状態、申告と公開情報の区別。金額は単位を、締切は日付のみか時刻まで判明しているかを明示する。欠損・未確認・取得失敗・古いデータを区別する。

項目ごとの根拠が必要な箇所は、現行返却データで足りるかを調べてから追加する。詳細ページへのリンクを付けただけで、公募要領の本文を確認済みとはしない。

### 第3段階：固定UIは必要な操作に絞る

生成UIでは選択結果の引き継ぎや操作の再現性を確保できない場合、既存のMCP Apps比較UIを改良する。ChatGPTの標準ブリッジによるツール呼び出しや会話への引き継ぎを実装する場合は、別の実装・検証項目として扱う。

独自UIを採用する場合、スマートフォンでは縦に読める表示とし、主要操作を絞る。単純な検索・照会では文章だけでもよく、すべての回答をUIに変える方針にはしない。[OpenAI UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)に沿って設計する。

## 後続に回す案

| 案 | 得られる価値 | 今回から分ける理由 |
| --- | --- | --- |
| 費用・自己負担の試算 | 設備費等を変更して負担の変化を確認できる | 費用区分別補助率、上限、例外、税区分、交付先、支払・入金時期を扱う検証済み計算が必要。モデルが作ったUI内の式だけを申請判断の根拠にしない。 |
| 申請準備のタイムライン | 締切・事前届・準備の順序を把握できる | 公式期限と利用者の予定を分け、未発表の来年度日程を確定表示しない仕組みが必要。 |
| 複数案件の保存・再開 | 専門家が企業ごとの検討を継続できる | 認証、保存範囲、共有権限、削除を含む別の設計が必要。Intelligent UIの状態保持だけで代替できない。 |
| 厚労省制度の統合検索・公式資料ナビ公開 | 検索範囲と根拠確認を広げられる | 既存コードはあるが別機能の公開準備が必要。UI改善と一括で有効化しない。 |

## 更新申請前の確認条件

- 同じツール結果について、UIとテキストで制度、公募回、金額、期限、出典、未確認事項が一致する。
- 0件、1件、複数件、取得失敗、古いキャッシュ、締切時刻不明を正しく扱う。
- 同名企業、公開情報と利用者申告の矛盾、年度・地域の変更を受けても、会社や評価の前提が混ざらない。
- チェック操作だけで申請資格を確定せず、相談文にも未確認事項が残る。
- 実際のChatGPTのChatで表示と操作を確認する。模擬画面やローカルHTMLだけをIntelligent UIの動作証拠としない。
- 利用可能なWeb・スマートフォン環境で確認し、Work等では表・文章による代替が成立する。特定のレイアウトが出ることだけを合格条件にしない。
- 別チャットでも準備状況が保存されるとは案内しない。UI状態が失われた場合に復元済みと装わない。
- 実装後の挙動に合わせて、既存の審査用テストとデモを更新し、日本語掲載文と新しいパッケージを作る。

更新説明は、実機で確認できた範囲に限って「候補比較、申請前の確認事項、専門家への相談準備を進めやすくしました。対応環境では対話的な表示を活用し、ほかの環境でも表と文章で利用できます」とする。「Intelligent UIを必ず表示」「申請可否を自動判定」「案件を永久保存」とは記載しない。
