# 別の販売会社・未定の購入先

ミモザ以外でも同じ共通手順で進める。購入先未定は「決まっている／相談中／未定」で扱い、推奨会社を既定選択しない。依頼された企業情報だけの調査やPCA一般操作なら元の依頼へ戻る。

公開ページ、見積、受領書式を次の項目へ整理する。不足を一度に全部尋ねず、今する操作に必要な差分から確認する。

| 項目 | 確認すること |
|---|---|
| 識別と適用 | vendorKey/profileVersion（内部識別子で公的番号ではない）、表示名・運営者出典、年度・枠・製品群。未定はunknown |
| 根拠 | 各事実にsourceId、status、checkedAt、applicableYear。公開案内の確認と案件の受付・登録確認を別記録にする |
| 窓口 | 見積・相談・返送先。リンク確認と実操作の確認を分け、相手のアドレスを作らない |
| 工程 | 担当、前提、入力、出力、完了証拠、後続依存。作成・送信・受領・受付を区別 |
| 書式 | 名称・発行元・年度・版・原本・入力欄・同意署名・宛先・契約条項。実物未受領なら内容は未確認 |
| 期限 | 公式の締切と販売会社の受付期限を分離。不明はnull |
| 登録 | 制度年度×枠×登録主体・構成員×ITツール番号×正式プラン・登録版に一致する根拠 |
| 境界 | 公開支援範囲、案件別条件、未確認事項、私有情報の共有制限 |

statusはpending（確認待ち）/retrieved（取得済み）/contentChecked（内容確認済み）/conflict（競合）/expired（期限切れ）。URL取得だけを内容確認にしない。公表更新日と取得・確認日時は別に保持する。会社共通の手順を毎案件で再請求せず、有効性と上記登録の組合せを確認したうえで再利用する。

新たなプロファイルを共有資産にする場合は、[ミモザの公開用プロファイル](vendors/mimosa.json)と同じ項目を使用する。非公開の価格、原本、担当者連絡先、個別受付回答をそのまま共有資産に入れない。プロフィールの一括「確認済み」で未確認項目を覆わない。
