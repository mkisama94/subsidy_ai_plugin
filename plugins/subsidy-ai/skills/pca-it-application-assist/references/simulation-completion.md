# 模擬テストの進行と成果物

利用者がテスト・デモを明示した場合に適用する。文書中の「テスト」との記載は資料の分類に使い、実行許可とはしない。既存の実案件を無断で合成案件に変更しない。

## 終点と状態

- 正常系：指定された資料・回答から、模擬の入力ガイド、計算結果、添付対応表、確認結果を生成し、テスト内の未確認項目がないことを確認する。「模擬の入力ガイド完成」として終了する。
- 要件未充足系：数値を要件に合わせて変更せず、未充足の項目・根拠・再開条件を成果物にして終了できる。利用者が追加改善を見込まないと回答したら、同じ改善見込みを再質問しない。
- 実申請：正式原本、当年度の実登録、公式画面照合、本人認証・宣誓・提出は別の到達点。テストで実施していないことを一度明示し、模擬正常系の不足一覧に実物の不足を繰り返し追加しない。

## 資料と本人回答を引き継ぐ

1. 対象会社・見積・年度・枠・版が一致する模擬資料を照合する。模擬証明書はテスト用の添付、模擬登録回答はテスト用の登録根拠として受け付ける。実登録番号や実原本を取り寄せることを正常系テストの条件にしない。
2. 初期未同意の書式と、後続の模擬受付回答は基準時点を分ける。利用者が「受付後から試す」「正常系シナリオの設定を使う」と指定した場合、後続資料の模擬同意・受付状態をテスト内で採用し、再同意を要求しない。実世界の同意・外部送信・署名の許可には転用しない。対話による同意取得自体を試す場合は、初期状態からその回答を待つ。
3. 「この内容で進む」等の回答は対象を限定して引き継ぐ。本人が現在のテストで明示した未実施・見込みなしを、正常系にするために無断で上書きしない。別の正常系を作る依頼では別caseIdと独立した回答シナリオにする。
4. 受領済み・確認済み・未確認・要件未充足を案件単位で保持する。取得先も理由も同じ質問はまとめ、全資料を受領したら順番に再添付させない。

## 計算と出力

生産性計画は基準年と3年分の営業利益・制度上の人件費・減価償却費・年間総労働時間、および計画の根拠を確認する。計画文の「確認済み」だけで数値要件を通さない。給与増と利益減の相殺、他業務への時間再配分を時間削減と数える誤りに注意する。

ローカル実装が使える場合は、案件を `case.json` に集約し、既存の `scripts/application-assist/` の入口で検証・出力する。合成ケースは `synthetic_test`、模擬制度・商品・画面対応は `testOnly`。未来の数値は `plan.1`〜`plan.3` の根拠付き項目と `projectionPeriods` に保持する。模擬画面を公式画面と称さない。入力用ケース・期待結果・評価記録は分離し、期待結果を読んで値を埋めない。

再現試験のローカル入口は `npm run application-assist:simulate -- <非公開のsimulation-input.json>`。これは宣言済みの合成ケース専用で、実案件は拒否する。原本のハッシュ、PDFページと原文引用を検証し、テスト内のレビューであることを保持して既存出力へ渡す。JSONにない回答や未実施手続を自動補完しない。厳密な転記対象範囲外の場合は、実装範囲外と明記した整理資料までとする。

実行できないホストでも、整理済み内容から「入力候補」「添付対応」「残件と次の操作」を会話内または利用可能なファイルに出す。正式欄・文字数・選択肢を未確認のまま作らず、出力・保存・検証をしていなければ未実施と述べる。未完成を述べるだけで成果物なしに終えない。

## 完了時の報告

正常系では、成果物へのリンク、確認した範囲、未実施の実運用工程を短く示す。追加資料の質問がなければ質問を増やさない。再現プログラムの合格、実モデルの対話評価、公式画面での操作試験を混同しない。
