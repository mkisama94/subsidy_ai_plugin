# PCA中継の段階公開

更新日：2026-11-08

## 方針

1. 開発中は公開MCPのPCA中継を無効にする。公開ツール一覧にassist_*を出さず、直接のtools/callも受け付けない。開発はローカルの明示的な有効化、またはPCA側の直接接続で行う。
2. プラグインの更新申請中も、公開MCPの中継は無効のままとする。スキルはツールの利用可否を確認し、存在しない場合に呼び出さない。申請資料ではPCA連携が後日有効化であることを明記する。審査で新機能の動作確認が必要になった場合は、公開範囲を黙って変えず、審査用の接続方法を調整する。
3. プラグインの承認・公開を確認してから、公開MCPの中継を有効化する。続いてOpenAI側のMCPスキャンと新ツールの承認・配信を確認する。プラグイン公開だけで新ツールも承認済みと扱わない。

会員向け高度支援を開始するには、上記の公開手順に加え、PCA側の認証・対象サービスの利用権限確認と操作ごとのアクセス制御が必要。匿名の無料デバッグ版は会員向けサービスの代わりにしない。開発環境への直接接続は明示的な模擬検証に限り、通常のスキルから非公開ゲートを迂回する経路にしない。

新ツールの配信後は、インストール済みホストの新規チャットで模擬案件の完走と無料検索の継続を確認する。

## 現在の設定

`wrangler.jsonc` の `PCA_RELAY_ENABLED` は `false`。公開Workerも同じ値へ変更した。設定変更はCloudflareの設定更新APIで行い、公開済みコードと他の20 bindings・その他の設定を保持した。開発途中のローカルコードをまとめてデプロイしていない。

2026-11-08 19:11 JSTに公開URLで確認：

- tools/listは従来の15ツール。assist_*は0件。
- assist_open_workspaceの直接呼出しは拒否。
- 匿名のsearch_subsidiesが成功。
- scripts/verify-production.mjsが成功し、既存ツール名と注釈が期待値に一致。

OpenAI管理画面のスキャン状態・キャッシュ更新は未確認。ホストに古い一覧が残っていても、サーバー側では中継ツールを実行できない。

PCA側の直接接続・Web・保存データは変更していない。今回の停止対象は補助金AI公開MCP経由の利用である。

## 再公開前に残る作業

- 会員向け分岐、一般支援への継続、認証・利用権限・保存同意の確認をスキルのローカル更新候補へ反映した。詳細と未実施の受入は[会員向け案内への変更記録](pca-membership-routing-2026-11-08.md)を参照。実ホストでの受入は別途必要。
- 公開検証を中継有効時の14ツールにも対応させる。無効時は従来15ツールを維持する。
- 中継の通信失敗を送信前と送信後の結果不明に分け、更新操作の安易な再試行を防ぐ。
- プラグインの更新申請・承認・公開を確認する。今回これらの手続は未実施。
