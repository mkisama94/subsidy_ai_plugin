# 推奨モデルの初回案内

## 案内するタイミングと目的

申請準備を始める最初の応答に、理由を含む1〜2文を添える。見積が添付済みなら読取り・短い確認と同じ応答にまとめ、モデル選択だけの往復を作らない。同じ相談で案内済みなら反復せず、利用者が選び方を尋ねた場合や利用不能など具体的な変更時にだけ補足する。

基準は「複数の資料と最新の制度要件を照合し、長いやり取りの条件を引き継ぐ作業に向く推論能力」。モデル番号の大小や発売日の新しさを性能の順序として扱わず、「GPT-6.1 Sol以上」を恒久的な必須条件にしない。上位モデルの使用で正確性・申請資格・採択を保証しない。

## モデル名を添えるとき

1. 既知の利用環境を使い、ChatGPT Work、Codex、通常のChat、APIの提供範囲を混同しない。BusinessのStandardシートだけで選択中モデルや個別アカウントの提供状況を確定しない。環境不明なら名前を省いた案内で進められる。
2. 具体名を案内する場合は、今回の相談で取得した現在の公式モデル案内・選択ガイドを確認する。同じ案内のための検索は繰り返さないが、後日再開して具体名を再案内する場合や提供変更が分かった場合は再確認する。知識内のモデル名や下記の記録だけで「最新」と呼ばない。公開情報の検索に見積・会社名・給与等を含めない。
3. 公式情報にある提供範囲・用途・利用負担から候補を選ぶ。後継モデルが案内されていれば同じ用途に適するか確認して候補を更新する。「6.2が出るはず」など未発表名を創作せず、新しい番号だけで推奨を置き換えない。
4. 情報を取得できない、内容が食い違う、提供範囲が分からない場合は具体名を省く。調査を繰り返して申請準備を待たせない。

現在の選択モデルは、ホストの明示情報または本人の回答がある場合だけ扱う。文体・回答の質・プラン名から推測しない。モデルの変更は本人の選択に委ね、切替済みと述べたり設定を無断変更したりしない。「どのモデルですか」「変更できましたか」を通常の必須質問にしない。推奨モデルが選べない場合も利用可能な環境で準備を続ける。

## 短い文例

具体名を現在の公式情報で確認でき、利用環境が合う場合の例：

> この作業は、見積・決算書・給与資料と補助金の条件を照合するため、推論に強いモデルをお勧めします。ChatGPT Workでは現在GPT-6.1 Solを目安に、モデル選択欄に表示される場合はご利用ください。

モデル名を確認できない場合の例：

> この作業は複数の資料と補助金の条件を照合するため、ご利用の環境で選べる、複雑な調査・推論に向くモデルをお勧めします。

文例のモデル名は表示時に確認した候補に置き換える。推論の設定・速度の説明や変更操作は求められた場合に絞り、画面で未確認のボタンや設定値を案内しない。初回はモデルの長い比較表を出さず、見積確認など次の作業へ続ける。

## 参照先と確認記録

- [OpenAI公式のモデル案内](https://learn.chatgpt.com/docs/models)：提供環境、モデルの用途、設定の考え方。
- [OpenAI公式のモデル選択ガイド](https://learn.chatgpt.com/docs/model-selection)：用途・利用負担の比較と同じ入力での評価。
- 2026-11-08の確認時点では、ChatGPT Work / Codexの申請準備でGPT-6.1 Solを候補とする。公式の複数資料・継続作業向けの説明からの用途上の推奨であり、本プラグインでの実モデル受入試験に合格したという記録ではない。

新モデルの公式公開を確認したことと、この申請手順の動作確認済みであることを分ける。後者には、モデル名・設定・試験日・対象手順と結果の記録が必要。過去申請の再利用、質問の理由、資料間の矛盾、賃金の計算、未確認事項を埋めない挙動を同じ合成資料で比較する。通常の顧客案内に評価管理の説明を詰め込まない。
