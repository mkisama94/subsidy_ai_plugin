# 申請支援の短い案内と取得待ちの分離

2026-11-08。利用者の今回の訂正を優先し、初回の全資料一覧・全数値確認を通常の案内から外した。目的は申請の手順案内と添付ミス防止。会計・税務・労務上の正確性レビューを通常業務にしない。

## 現在の動作

- 見通しは「見積」「手元資料」「取り寄せる書類」「申請内容確認・提出」の4区分を標準とする。章分けのように行動・取得先・待ち時間でまとめ、各場面の項目は3〜4個を目安にする。待ち時間が長ければ取得だけ先行できる。
- 決算書の表示は会社、記載された期数または期間、売上、利益の種類と額。人事資料は期間・人数・受領状況程度。全科目表・個人明細・検算件数や全数値への再承認は標準工程から外す。
- 会社・期間違い、欠月、読めない箇所、単位の誤り、申請入力に影響する矛盾は短く示す。正式入力に必要な計算・本人の計画・同意の確認は残す。
- 手元資料は一括添付を維持。登記と納税証明書の取得、メールで届く同意書の確認・返送は別工程にする。一緒に受領できた資料はそのまま処理し、工程順のために再添付させない。
- 取得タスク・リマインダーは利用可能な連携で提案し、本人の依頼と具体的な日時等に基づいて登録する。国の締切・販売会社締切・取得目標を別管理する。
- Gmailは単発検索と継続監視の能力を区別する。監視には対象アカウント・検索範囲・頻度・停止条件と対応する定期実行機能が必要。実行成功前に登録済みとせず、無変化の通知や重複通知を避ける。到着確認を同意・署名・返送の許可としない。

通常回答は200〜400字程度を目安とし、必要な判断を省く文字数制限にはしない。詳細一覧や出典解説は必要時に展開する。
